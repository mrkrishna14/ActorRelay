# HANDOFF: P&ID and fallback simulator

## P&ID: `web/public/pid-tk-101.svg`
- Original schematic drawn for this project (generated by hand-written layout code; no external source). 1500x1000 viewBox, white background rect, ISA-style instrument bubbles (controllers with a center bar = control room), solid blue liquid lines, solid orange steam/condensate lines, dashed grey signal lines, legend bottom-left, title block bottom-right ("TK-101 Heated Hold Tank — Simulated Plant").
- Content: Feed -> P-100 (centrifugal pump) -> FI-101 / TI-100 on the feed line -> top of agitated tank TK-101 (2.0 m dia x 4.0 m, NLL 2.0 m). Submerged steam coil E-101 inside. Shared steam header (6 barg, shared by Plant A and Plant B) -> FT-201 -> TV-101 (globe valve, diaphragm actuator) -> PI-201 -> E-101 -> steam trap -> Condensate return. Bottom outlet -> LV-101 -> FI-102 -> To downstream. Loops: TT-101 -> TIC-101 (SP 75 C) cascade -> FIC-201 -> TV-101; LT-101 -> LIC-101 (SP 2.0 m) -> LV-101.
- Component groups (bare tags, unique; the web picks the plant via its switcher): `<g id="P-100">`, `<g id="TK-101">`, `<g id="LV-101">`, `<g id="E-101">`, `<g id="TV-101">`. Each wraps the symbol and its tag label text.
- Empty live-value placeholders (`<text class="live-value" font-size="14" font-weight="bold">`, no transform, one inside each group): `P-100-value` (under the pump), `TK-101-value` (under the tank label, left of the tank), `E-101-value` (inside the tank next to the coil), `TV-101-value` (under the valve), `LV-101-value` (under the valve). Set `textContent`, e.g. `svg.getElementById("LV-101-value").textContent = "67.2 %"`.
- Other ids: `background`, `frame`, `legend`, `title-block`, markers `arr-liq`, `arr-stm`, `arr-sig`. Instruments (FI-101, TI-100, TT-101, TIC-101, FIC-201, FT-201, PI-201, LT-101, LIC-101, FI-102) are `<g class="instrument">` without ids.

## Fallback: `bridge/fallback.ts`
- Run: `bun bridge/fallback.ts` (127.0.0.1:7300, 1 tick/s). Env: `PORT` or `SIM_PORT`, `SIM_FAST=1` (10 ticks/s), `GLUE_URL` (default http://127.0.0.1:7200).
- Same endpoints and JSON shapes as `bridge/live_sim.py`: GET /health, GET /snapshot[?plantId=], POST /setpoint (idempotent on proposalId, same ranges and error strings), POST /reset, GET /observed?proposalId= (200 observation, 202 `{proposalId, pending:true}`, 404 unknown). Pushes /mirror per component per tick and /observed after 5 ticks to glue (best effort).
- Mode header: every response carries `X-Sim-Mode: fallback`. live_sim does not send this header, so its absence means the live model is answering.
- Model: the linear approximation from TASK2.MD (first-order lag, alpha 0.7 per tick; LV-101 = speed + 4 x decaying overshoot pulse; steam 29.7 x speed + 48; duty 17.43 x speed + 27; TV-101 0.36 x speed + 32.5 plus header correction; temp dips 0.05 x |delta speed| then recovers; speed >= 95 saturates LV-101 at 100 and level rises 1 %/tick; shared header equation as in live_sim).
- Test: `python bridge/tests/test_fallback.py` (starts bun on port 7399, or `FALLBACK_TEST_PORT`; stops it afterwards). Covers 65 -> LV 65-68 and temp within 1 C, 85 -> LV >= 85 within 3 ticks plus header drop on plant-b, 100 -> LV 100 and level rising, idempotency, 202/404/400 shapes.
- Limitations: temperature dip is smaller than the full model (1.75 C for 50->85 vs ~4 C); no level dynamics except saturation and level setpoint tracking.
